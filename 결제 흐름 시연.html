    결제과정

    계좌 잔액
    날짜가 빠른 순, 같은 날이면 우선순위가 높은 순으로 결제안 단위로 결제합니다.
    화면의 에이전트·결제 요청·금액은 모두 예시이고, 아래 판정 기준은 시연을 위해 임시로 정한 값입니다.
    • 작업단위 배분: 프롬프트를 문장 단위로 쪼개 낱말(조카·선물, 사무환경, 구독·갱신, 출장, 여행·호텔, 마케팅·가게)로 에이전트를 정함. 각 에이전트가 내는 결제 요청은 예시 값
    • 결제안: 한 에이전트가 낸 결제 요청은 모두 한 묶음(결제안)으로 함께만 결제. 서로 다른 에이전트의 요청은 절대 묶지 않음
    • 가용 예산 = 계좌 잔액 − 결제 예정 합계
    • 목적·수치 검사: 결제안 안에서 허가되지 않은 목적, 금액 없음, 가용 예산보다 큰 금액이 하나라도 나오면 그 결제안을 통째로 폐기
    • 중복 검사: 독점 표기가 없는 요청끼리 비교. 서로 다른 결제안에 같은 항목(예: 노트북)이 있으면 양쪽 금액을 더 낮은 쪽으로 통일하고, 그 항목을 이름으로 단 선으로 두 결제안을 연결
    • 날짜가 붙은 항목: 요청 앞에 날짜가 붙어 있으면(예: 하노이 호텔과 여행지 호텔) 날짜가 다르면 다른 항목으로 봄
    • 독점 표기: 표시한 요청은 같은 항목이 있어도 중복 검사에서 빠지고 원래 금액 그대로 결제
    • 등록: 우선순위가 높은 결제안부터 스케줄러에 올림(동률이면 글자 순). 연결된 결제안이 이미 올라가 있으면 겹치는 항목은 이미 올라간 쪽에서 결제하므로 비용에서 빼고 계산. 넣으면 예산을 넘는 결제안이 나오면 엔진이 멈추고 묻습니다: 그 결제안만 잠재 작업으로 보내고 계속할지, 거기서 잘라 아래 결제안까지 모두 잠재 작업으로 보낼지
    • 납부일: 에이전트 카드의 납부일 칸(결제안 전체에 적용). 비우면 당일 결제
    • 다시 실행: 2페이지에서 다시 실행하면 이전 실행이 등록한 미결제 건을 지우고 새 결과로 교체
    • 결제과정: 날짜가 빠른 순, 같은 날이면 우선순위가 높은 순. 실패는 각 결제의 "실패 가정" 표시로 정하며, 기본 예시는 기차표가 실패
    • 실패 처리: 실패한 결제안은 이미 결제된 요청까지 취소·환불하고, 그 결제안과 아직 결제되지 않은 더 낮은 우선순위 결제안, 그리고 실패한 결제안에 겹치는 항목을 맡긴 결제안을 임시 공간으로 이동. 재탐색 결과(대체 경로와 금액)는 예시
    결제 흐름 뒤의 실제 구성

    세부 사용 기술

    1. 01

      에이전트 탐색

      UCP 기반 탐색으로 인젝션 가능성이 낮은 데이터를 먼저 추출합니다.

      웹 기반 비정형 데이터를 분석할 때는 프롬프트 인젝션 방어를 겹겹이 둡니다.

      • 키워드 기반 필터
      • 단어사전 기반 필터
      • 문법 검사 필터
      • 맥락 어색함 판별 보안 에이전트
      • 멀티모달 인젝션 방어용 데이터 변형 장치
      • 무해성 사전검사용 소형 모델
    2. 02

      Safety Runtime

      결정론적 엔진입니다. 탐색 단계의 방어를 거치고도 남은 문제를 여기서 걸러냅니다.

      시연의 목적·수치 검사(결제안 통째로 폐기)가 이 단계입니다.

    3. 03

      충돌·중복 검사

      최적해를 구하기 위해 솔버를 사용합니다.

      • Z3
      • OR-Tools

      시연의 중복 항목 통일, 결제안 그래프, 우선순위 배정이 이 단계입니다.

    4. 04

      Executor

      결제 안전을 위해 에이전트 결제 규격으로 실제 결제를 집행합니다.

      • Google AP2
      • Visa Trusted Agent Protocol
      • Mastercard Agent Pay for Machines
      • Skyfire
      • Stripe SPT

    OPA에이전트 권한 검사 등 정책 판단
    PostgreSQL상태·예약·이벤트·감사 기록 저장
    UCP 규격 + Saga compensation배송 관리, 취소 시 원자성을 유지한 결제 복구 등 사후 기능
